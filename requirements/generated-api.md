# Generated API Requirements

How schema declarations map to C#. The mapping is fixed by convention and cannot be configured.

## API-001 General Shape of Generated Code

Acceptance criteria:

- Each declaration produces one generated source file named `{FullyQualifiedName}.g.cs`, renamed if it would be equal to another ignoring case (API-002). One more file, `BequadroSchema.g.cs`, holds the schema set's fingerprint (SER-015).
- Every generated file starts with `// <auto-generated/>` and `#nullable enable`. It compiles without warnings under `<Nullable>enable</Nullable>`, `<AnalysisMode>All</AnalysisMode>` and `TreatWarningsAsErrors`, with no extra suppressions in the consumer. The one exception is a root-namespace declaration named like a namespace in a referenced assembly (API-002).
- Generated types go in the C# namespace equal to the schema namespace. Declarations in the root schema namespace go in the global namespace, and so does the fingerprint's class, `BequadroSchema`.
- Every generated type is `public`. Every generated table, struct and union is `partial`, so consumers can add members, interfaces and constructors in their own files.
- References to other types in generated code are fully qualified with `global::`, so consumer `using` directives and type names can't change their meaning.
- A run of `///` comments in the schema becomes a `<summary>` XML doc comment on the generated element, with each line trimmed and the text XML-escaped. A character that ends a line in C# (a carriage return, U+0085, U+2028 or U+2029) also ends a documentation line, and characters that XML can't contain (control characters other than tab, U+FFFE, U+FFFF and unpaired surrogates) become U+FFFD, so the comment compiles without warnings with `GenerateDocumentationFile`.
- Identifiers that are C# keywords, contextual keywords included, are escaped with `@`. So are type names made only of lowercase ASCII letters, such as `monster` or `record`, which C# warns about (CS8981) because a later version may make them keywords.
- Generated code doesn't use contextual keywords that a type with that name would capture: it declares locals with their types, never with `var`.

Design decisions:

- A type named like a contextual keyword is escaped rather than renamed (NAM-002), because `@record` is the identifier `record`, so the C# type keeps its schema name. Escaping is enough for every such name. A type named `var`, `dynamic`, `nint` or `nuint` still takes over that word in code that can see it, which is why generated code never uses those words; consumer code in the same namespace sees the type, as it would see a hand-written one.

## API-002 Naming

Acceptance criteria:

- Table, struct, enum and union names, enum value names, union member labels and namespace segments are used as written.
- Table and struct field names become PascalCase. The name is split on `_`, the first character of each non-empty segment is upper-cased, the rest of each segment is kept as written, and the segments are joined. For example, `parent_index` becomes `ParentIndex`, `y_axis_reference` becomes `YAxisReference`, `force_11` becomes `Force11`, `x` becomes `X`, and `fooBar` becomes `FooBar`. A name made only of underscores, such as `_` or `__`, has no segment to join, so it is kept as written.
- Names that C# can't use as written are renamed (NAM-002). Most follow from one rule: a type and each of its members need distinct names, where a member's names include its metadata names. A property `P` also takes the names of its accessors, `get_P` and, if it has a setter, `set_P`, and an operator takes its method name, such as `op_Equality`. The names generated in each type are:
  - in a table: `Serializer` and `get_Serializer`, `ToString`, and each field's property with `get_` and `set_`; with `bequadro_value_equality` also `Equals`, `GetHashCode`, `op_Equality` and `op_Inequality`;
  - in a struct: `Equals`, `GetHashCode`, `ToString`, `op_Equality` and `op_Inequality`, and each field;
  - in a union: `ItemKind`, `Kind`, `get_Kind`, `Value`, `get_Value`, `HasValue`, `get_HasValue`, `TryGetValue`, `Equals`, `GetHashCode`, `ToString`, `op_Implicit`, `op_Equality`, `op_Inequality`, the private fields `_kind`, `_reference` and `_value` followed by digits, and each label's property with `get_`. `HasValue` and `get_HasValue` count whether or not the union has `HasValue` (API-006), so adding `bequadro_exclude_none` never renames a label.
- So the renamed names are:
  - a declaration named like a name generated in it, such as a table named `Serializer` or `get_Serializer`, a struct named `op_Equality`, or a union named `Kind`, `get_Value`, `op_Implicit` or `_kind`;
  - a field or union label named like a generated name of its type, such as a table field `Serializer` or a label `get_Kind` or `op_Equality`;
  - a field or label that is, or whose property's accessors are, its type's name, such as field `x` in table `get_X`;
  - a field or label named like a member every type inherits from `object`, which it would hide (CS0108): `ToString`, `Equals`, `GetHashCode`, `GetType`, `MemberwiseClone`, `Finalize` and `ReferenceEquals`;
  - a label `get_L` beside a label `L`, as their final names: the label that is the getter yields, whichever comes first;
  - an enum value or union label named `value__`, the name .NET gives an enum's value field (CS0076), because labels are also members of `ItemKind`;
  - a declaration named `System` or `Bequadro` in the root namespace;
  - a declaration named `BequadroSchema` in the root namespace, and a top-level namespace `BequadroSchema`, which would conflict with the fingerprint's class (SER-015);
  - a top-level namespace `System`, so the namespace `System.Foo` becomes `System_.Foo`;
  - a declaration or namespace in the namespace `Bequadro` named like a runtime type or namespace: `FlatBufferSerializer`, `UnionNone`, `UnionUnknown` or `Internal`, so the namespace `Bequadro.Internal` becomes `Bequadro.Internal_`;
  - a declaration with the same full name as a namespace, or the other way round, which C# doesn't allow (CS0101). Whichever appears first (NAM-002) keeps its name.
- Generated file names (API-001) that are equal ignoring case, as Roslyn requires them not to be, are renamed, and so is a declaration's file that would be `BequadroSchema.g.cs` ignoring case, such as that of a root table `bequadroschema`. The types keep their names.
- For example, the fields `foo_bar` and `fooBar` of one table become `FooBar` and `FooBar_`, and a table field `Serializer` becomes `Serializer_`.

Design decisions:

- Renaming instead of rejecting follows NAM-001.
- The reserved names come from what each type generates, through C#'s rule for member names, rather than from a list of names that happened to fail. A new generated member therefore adds its names, with its accessors or operator names, to one place.
- When a field's accessor would be its table's name, the field is renamed, not the table, as for a field with its table's name: declarations are named before their members, so the table's name is already final.
- A label that is another label's getter is renamed after the other labels have their final names, because only those decide whether the two collide. Labels are handled shortest first, so the outcome doesn't depend on their order.
- A namespace in `Bequadro` follows the same rule as a declaration there. `Bequadro.FlatBufferSerializer` would compile as a namespace, because the runtime type is generic, but one rule for both is simpler to state and to check.
- Only `System`, `Bequadro` and `BequadroSchema` are reserved in the root namespace: generated code refers to the first two, as `global::System...` and `global::Bequadro...`, and declares the third. A root-namespace declaration named like a root namespace of another referenced assembly, such as `Microsoft`, is expected to compile with warning CS0437 (a type conflicts with an imported namespace) wherever generated code refers to it as `global::Microsoft`. Hand-written C# with that type name gets the same warning, and the generator can't tell which assemblies a project references. Declaring the type in a namespace avoids it.

## API-003 Enums

Acceptance criteria:

- `enum Color : ubyte { Red, Green = 3 }` generates `public enum Color : byte { Red = 0, Green = 3 }`, with every value written explicitly.
- Underlying types map as `byte → sbyte`, `ubyte → byte`, `short → short`, `ushort → ushort`, `int → int`, `uint → uint`, `long → long` and `ulong → ulong`, and likewise for the sized aliases.

## API-004 Structs

Acceptance criteria:

- A struct generates `[StructLayout(LayoutKind.Auto)] public partial struct Name : global::System.IEquatable<Name>`.
- Structs are unmanaged. The runtime interface they implement requires it, so a consumer partial that adds a reference-type field is a compile error.
- Each schema field becomes a public, mutable instance **field** of the mapped C# type (API-008), in declaration order.
- A consumer partial may add unmanaged instance fields, without warning CS0282. They aren't written or read, and they keep their values wherever the struct is held, unions included (API-006).
- No constructor is generated. The implicit parameterless constructor gives every field its zero value, and consumers may add constructors in a partial file.
- Value equality is generated: `Equals(Name)`, `Equals(object?)`, `GetHashCode()`, `==` and `!=`. Two values are equal when every field is equal under `EqualityComparer<T>.Default`, so `NaN` equals `NaN`, matching `ValueTuple` semantics.
- `ToString()` returns `Name { Field1 = value1, Field2 = value2 }`.

Design decisions:

- Structs are always value types with fields, which is FlatSharp's `fs_valueStruct`. Structs are small, fixed-size values, so a value type saves an allocation for each, and fields let code change them in place.
- FlatBuffers structs only contain scalars, enums and structs, so requiring them to be unmanaged costs nothing. It lets unions overlap their struct members safely (API-006).
- The layout in memory is `Auto`, because the serializer reads and writes each field at its schema offset and never copies a struct as memory. C# warns about a partial struct with fields in more than one declaration unless its layout says their order doesn't matter (CS0282), so without it, adding a field in a partial file would fail a build with warnings as errors.

## API-005 Tables

Acceptance criteria:

- A table generates `public sealed partial class Name`. A consumer partial declaration doesn't need to repeat `sealed`.
- It has an explicit public parameterless constructor, so one still exists when a consumer adds other constructors in a partial file.
- Each field becomes a public auto-property `{ get; set; }`, non-virtual, of the mapped C# type (API-008).
- `required` schema fields become `required` C# properties with non-nullable types.
- Non-required fields of reference types (strings, tables, vectors) are nullable (`T?`). Non-required struct fields, and non-required fields of unions declared with `bequadro_exclude_none`, are `Nullable<T>`.
- Non-required fields of unions that allow `NONE` (the default) are not nullable: `NONE` means absent, which is the FlatBuffers meaning of a union field with no value.
- Scalar and enum fields with a non-zero default get a property initializer, for example `= 1.0` or `= global::Ns.CoordinateSystemType.Local`. Optional scalars (`= null`) are `Nullable<T>`, initially `null`.
- When the project sets `BequadroRequireScalarsWithoutDefault` (CON-006), scalar and enum fields with no default in the schema are also `required` C# properties, so an object initializer that doesn't set one is a compile error (CS9035). A field with any default written in the schema, `= 0` and `= null` included, isn't made required. Only the C# property changes: the field isn't required on the wire, so writing still leaves it out when it equals its default (SER-004), and parsing a buffer without it gives the default instead of throwing (SER-009).
- By default, tables keep reference equality: `Equals` and `GetHashCode` are not overridden.
- A table declared with `bequadro_value_equality` (SCH-005) has value equality instead:
  - It implements `global::System.IEquatable<Name>`, and has `Equals(Name?)`, `Equals(object?)`, `GetHashCode()`, `==` and `!=`. The operators accept null, and null equals only null.
  - Two instances are equal when every field is equal.
  - Vector fields are equal when both are null, or when they have the same length and equal elements, whatever their implementations: an array equals a `List<T>` with the same elements. A null vector isn't equal to an empty one, because they are different on the wire (SER-004).
  - Every other field compares under `EqualityComparer<T>.Default`: scalars as `ValueTuple` does, so `NaN` equals `NaN`; strings by ordinal comparison; structs and unions by their generated equality (API-004, API-006); and tables by their own equality, which is by value only if the referenced table also has the attribute.
  - `GetHashCode` is consistent with `Equals`, and combines every field, with vectors hashed element by element.
  - Sharing on write and read still follows instances, not equality: two equal but separate instances are written twice and parse as two instances (SER-003, SER-011).
- `ToString()` returns `Name { Field1 = value1, ... }`, with each value formatted as string interpolation formats it, as a record's `ToString` does: a null value is empty, a vector shows its type name rather than its elements, and a table, struct or union shows its own `ToString()`.
- `public static global::Bequadro.FlatBufferSerializer<Name> Serializer { get; }` is generated on every table (SER-001).
- No copy constructor, `OnInitialized` hook or metadata attributes are generated.

Design decisions:

- Every table gets a serializer, because tables are serializable roots in FlatBuffers anyway. The per-table cost is one static property, and it removes the need for an attribute.
- Properties are non-virtual. FlatSharp made them virtual so lazy subclasses could override them, and Bequadro has no lazy mode.
- `ToString()` formats values as records do, which C# developers already know. Listing vector elements would make the output of a large graph unbounded, and a table's elements could repeat the tables around them.
- Tables are sealed. FlatSharp tables were unsealed for its lazy subclasses, and Bequadro has none. A consumer subclass would be a trap: writing one silently drops whatever the subclass adds, and parsing always produces the generated class, so a round trip would change the type. Partial declarations cover adding members. Sealing also keeps value equality symmetric without comparing runtime types.
- A scalar field without a default that code forgets to set is silently 0. `BequadroRequireScalarsWithoutDefault` makes the compiler catch that. Writing `= 0` in the schema states that 0 is a meaningful default, so such a field stays optional.
- Required scalars stay optional on the wire. FlatBuffers can't tell a scalar equal to its default from an absent one, because writers leave defaults out, and `flatc` rejects `required` on scalars (BQ2008). Requiring them on the wire would reject buffers from other writers, and from older schemas without the field.
- Reference equality is the default, so that table instances can key dictionaries, which identity preservation (SER-011) makes useful. Value equality is opt-in, for small tables used like structs, which are tables only so that fields can be added to them later.
- Value equality applies only as deep as the attribute does. A table without it compares by reference wherever it appears, so adding the attribute to one table never changes how another compares.
- Tables are mutable, so, as with a record class, changing a table with value equality while it is a key in a dictionary or set makes it unfindable. Comparing or hashing a reference cycle of tables with value equality overflows the stack, as it does for records. Such a cycle can't be written anyway (SER-003).
- An older reader drops fields added by a newer schema (SER-009), so two buffers that differ only in those fields parse as equal tables.

## API-006 Unions

Acceptance criteria:

- A union generates `[global::System.Runtime.CompilerServices.Union] public readonly partial struct Name : global::System.IEquatable<Name>, global::System.Runtime.CompilerServices.IUnion`. C# pattern matching (`switch`, `is`) therefore works on the union's cases, and a `switch` that misses a case produces warning CS8509.
- The cases are:
  - each member type;
  - `global::Bequadro.UnionNone`, unless the union is declared with `bequadro_exclude_none` (SCH-008);
  - `global::Bequadro.UnionUnknown`, unless the union is declared with `bequadro_exhaustive` (SCH-008).
- `UnionNone` and `UnionUnknown` are public `readonly record struct`s in the runtime. `UnionUnknown` has a `byte Discriminator`. Their `ToString()` returns `NONE` and `Unknown(n)`.
- A nested `public enum ItemKind : byte` has `NONE = 0` plus one value per member label, equal to its discriminator.
- `public ItemKind Kind { get; }` gives the active member. `default(Name)` has `Kind == ItemKind.NONE`. For an unknown member, `Kind` is the raw discriminator cast to `ItemKind`.
- For each member with label `L` and type `T`:
  - a constructor `public Name(T value)`, which throws `ArgumentNullException` if a reference-type `value` is null;
  - an implicit conversion `public static implicit operator Name(T value)`;
  - a property `public T L { get; }`, which returns the value when `Kind == ItemKind.L` and otherwise throws `InvalidOperationException`;
  - `public bool TryGetValue([NotNullWhen(true)] out T? value)` (without `?` and the attribute for struct members), which returns true and the value when the union holds `L`, and false and `default` otherwise.
- When `UnionNone` is a case: a constructor and an implicit conversion from `UnionNone` give `default(Name)`, and `TryGetValue(out UnionNone)` returns true for `NONE`.
- When `UnionUnknown` is a case: the constructor `Name(UnionUnknown value)` throws `ArgumentOutOfRangeException` if the discriminator is 0 or a member's, and `TryGetValue(out UnionUnknown)` returns true for any other discriminator.
- When `UnionNone` is not a case, `public bool HasValue` is false for `default(Name)` and true otherwise.
- `public object? Value { get; }` (from `IUnion`) returns the held case: the member, a `UnionNone`, a `UnionUnknown`, or null for `default(Name)` when `UnionNone` is not a case.
- Pattern matching on member types doesn't box struct members or allocate.
- Equality: two unions are equal when their `Kind`s are equal and, for members, their values are equal: table members under `object.Equals` (by reference unless the table overrides `Equals`) and struct members by value. `GetHashCode`, `==` and `!=` are consistent with this.
- `ToString()` returns `Name { value }`, where `value` is `Value`.

Design decisions:

- The defaults follow FlatBuffers, where `NONE` is a valid value and readers tolerate members added by newer schemas. The attributes opt in to the stricter behavior that FlatSharp had.
- `NONE` and unknown members are case *types*, not `null`, because the compiler doesn't require a `null` arm for a union. With case types, forgetting to handle them is a warning. Their constructors exist because the compiler takes a union's cases from its single-parameter constructors.
- The union is a custom `[Union]` struct, not a `union` declaration. A `union` declaration identifies cases by type only, so it can't keep member labels or `Kind`. It also stores every case as `object`, which boxes struct members. The generated struct switches on its discriminator, so the serializer never tests types.
- Storage: table members share one `object` field, and each struct member has its own typed field. With two or more struct members, the layout is explicit and the struct fields overlap, so the union is no larger than a reference, the discriminator and the largest struct. The struct fields come last, after the discriminator, because a consumer partial may add fields to a struct (API-004), which makes it larger than its schema size: nothing placed after it could be overwritten. A consumer partial can't add instance fields to such a union itself.
- `Match`, the old `TryGet` and visitor APIs are gone: `switch` replaces them, it is checked for exhaustiveness, and it allocates nothing. The compiler requires the `TryGetValue` name.
- A member type can't appear twice (BQ4002), because the constructors, conversions and `TryGetValue` overloads couldn't tell the two apart. This is the one restriction beyond `flatc`'s that remains (NAM-001).

## API-007 Vectors

Acceptance criteria:

- A vector of T maps to `global::System.Collections.Generic.IReadOnlyList<T>`.
- Consumers may assign any implementation, such as an array, `List<T>` or collection expression. The serializer accepts all of them, and writes the same bytes for equal elements whatever the implementation.
- Parsing produces arrays (`T[]`) typed as `IReadOnlyList<T>`.

Design decisions:

- `IReadOnlyList<T>` is the only vector type. It accepts arrays and lists alike, and a single type keeps the generator and the generated API simple.

| Schema type | C# type |
| --- | --- |
| `bool` | `bool` |
| `byte` / `int8` | `sbyte` |
| `ubyte` / `uint8` | `byte` |
| `short` / `int16` | `short` |
| `ushort` / `uint16` | `ushort` |
| `int` / `int32` | `int` |
| `uint` / `uint32` | `uint` |
| `long` / `int64` | `long` |
| `ulong` / `uint64` | `ulong` |
| `float` / `float32` | `float` |
| `double` / `float64` | `double` |
| `string` | `string` |
| enum `E` | `E` |
| struct `S` | `S` |
| table `T` | `T` |
| union `U` | `U` |
| `[X]` | `IReadOnlyList<X>` |

Nullability and `required` follow API-005.
